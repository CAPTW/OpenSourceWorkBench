# OpenFOAM template v12 pFinal fix implementation

## 1. Status

Implementation complete (`OSW-EXP-144`).

- Implements the algorithm-aware `system/fvSolution` `pFinal` fix designed in
  [OpenFOAM template v12 pFinal fix design](openfoam_template_v12_pfinal_fix_design.md)
  (`OSW-EXP-143`) and tracked by GitHub issue #19.
- **No live solver validation** in this gate: no OpenFOAM execution, no
  `blockMesh`/`icoFoam`/`simpleFoam`/`foamVersion` invocation, and no unit test
  that requires an installed OpenFOAM.
- **No issue mutation**: issues #18 and #19 stay OPEN.
- **No certification**, production-readiness, bundled-solver, or
  native-Windows-validation claim.
- Package metadata remains `0.1.5rc1`; public prerelease remains `v0.1.5-rc1`.

## 2. Public API / option names

No new public API or CLI option. The `pFinal` entry is derived internally from the
already-selected solver/algorithm (cavity is always `icoFoam`; the duct follows
its `solver` field). Existing surfaces are unchanged:
`generate_cavity_case`, `generate_duct_case`, `generate_openfoam_case`, and
`openfoam-write-case` behave as before, now emitting `pFinal` for PISO cases.

## 3. Algorithm policy

`pFinal` is gated on the **algorithm**, not on the property-file layout:

- PISO / `icoFoam` cases → emit `pFinal`.
- SIMPLE / `simpleFoam` cases → do **not** emit `pFinal`.

This is orthogonal to `OpenFOAMPropertyFileLayout` (legacy vs
`foundation_v11_plus`): the `fvSolution` is identical across property-file
layouts, so a foundation cavity and a legacy cavity get the same `pFinal`.

## 4. PISO / icoFoam behavior

The cavity (always `icoFoam`) and any duct configured with `solver="icoFoam"`
now generate a `system/fvSolution/solvers` dictionary containing `p`, `pFinal`,
and `U`, followed by the `PISO` block. The `pFinal` entry is:

```
    pFinal
    {
        $p;
        relTol          0;
    }
```

It reuses the `p` solver via the OpenFOAM `$p` macro and tightens `relTol` to `0`
for the final corrector, matching the OpenFOAM 12 `icoFoam` cavity tutorial
convention.

## 5. SIMPLE / simpleFoam behavior

The duct default (`simpleFoam`, SIMPLE) is **unchanged**: its
`system/fvSolution/solvers` still contains only `p` and `U`, followed by the
`SIMPLE` block, with no `pFinal`. The generated bytes are identical to the
pre-fix output (the duct golden fixture is unchanged).

## 6. fvSolution generation details

- New module constant `_PFINAL_SOLVER_BLOCK` holds the `pFinal` dictionary text
  (with a literal `$p`, since it is injected as a `string.Template` substitution
  *value* and is not re-parsed).
- A `$pfinal_block` placeholder was added to the `fvSolution` `solvers` dictionary
  between the `p` and `U` blocks in the cavity embedded template, the on-disk
  cavity template (`src/osw/solvers/openfoam/templates/cavity/system/fvSolution`),
  and the duct embedded template.
- The cavity context (`_template_context`) always sets `pfinal_block` to
  `_PFINAL_SOLVER_BLOCK` (cavity is always PISO).
- `_duct_solver_settings` sets `pfinal_block` to `_PFINAL_SOLVER_BLOCK` for
  `icoFoam` and to `""` for `simpleFoam`, so the empty case renders exactly the
  previous SIMPLE output.

## 7. Template / golden fixture updates

- Updated `src/osw/solvers/openfoam/templates/cavity/system/fvSolution` (added the
  `$pfinal_block` placeholder).
- Updated `tests/golden/openfoam/cavity/system/fvSolution` to include the rendered
  `pFinal` entry.
- `tests/golden/openfoam/duct/system/fvSolution` is **unchanged** (duct default is
  `simpleFoam`).
- OSW-EXP-142 `constant/physicalProperties` fixtures are untouched (a `constant/`
  concern, independent of `fvSolution`).

## 8. Test coverage

`tests/unit/test_openfoam_template_v12_pfinal.py` covers: foundation cavity
`fvSolution` has `pFinal` (with `$p` and `relTol 0`) and keeps `p`; foundation
cavity still emits `physicalProperties`; legacy cavity keeps `transportProperties`
and still has `pFinal`; `pFinal` ordering (between `p` and `U`); default duct
(`simpleFoam`) has no `pFinal` and intact property files; `icoFoam` duct (legacy
and foundation) has `pFinal`; CLI cavity emits `pFinal`; CLI duct default has no
`pFinal`; and a generator-source scan asserting no subprocess execution. The
cavity golden test now asserts the `pFinal` layout. No test runs OpenFOAM,
requires an OpenFOAM executable, installs dependencies, or uses the network;
generated cases use `tmp_path`.
